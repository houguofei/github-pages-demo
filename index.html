部署三步走

  1. 在 GitHub 新建仓库，把本文件夹里的文件推到 main 分支根目录。
  2. 仓库 Settings → Pages → Source 选 Deploy from a branch，分支 main、文件夹 / (root)，保存。
  3. 等 1–2 分钟，打开 https://<用户名>.github.io/<仓库名>/。

静态文件必须放在发布源文件夹的根目录。如果把本站放进子目录，URL 末尾要带该子目录。

上线前检查清单

  • 资源用相对路径（./styles.css），不要写 /styles.css——项目站点位于子路径下，绝对路径会 404。
  • 放了空的 .nojekyll 文件，阻止 Jekyll 构建时忽略 _ 开头的目录。
  • 备了 404.html，链接写错时给用户一个正常页面而不是 GitHub 默认 404。
  • 免费账号只能用公开仓库发布 Pages；私有仓库发布需 Pro/Team/Enterprise。
  • 站点公开可访问，不要放密钥、内网地址、个人隐私数据。

遇到问题

打开是 404
确认 Pages 已启用、分支/文件夹选对、Actions 或构建日志无报错；刚保存后有 1–2 分钟延迟。
样式没生效
多半是路径问题：项目站点要相对路径，或构建工具里把 base 配成 /仓库名/。
改了没变化
浏览器缓存，按 Ctrl+F5；再确认最新一次部署是成功的。
SPA 刷新子路由 404
把 index.html 复制一份为 404.html，由前端路由接管。
